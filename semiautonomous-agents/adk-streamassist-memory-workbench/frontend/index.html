1. "ADK Intercepts StreamAssist Mid-Turn"
(Turns 8 & 22)		 The transcript claimed ADK invokes StreamAssist as a "streaming cognitive engine" while ADK intercepts its intermediate tool loop and injects ephemeral 50-page document frames into each turn. StreamAssist is defined on google.cloud.discoveryengine.v1.AssistantService (assistant_service.proto, 45-min RPC deadline), not a raw LLM completion endpoint. It runs its own closed-loop DolphinServer planner, DRIP query rewriter, and server-side Spanner Session. ADK cannot intercept StreamAssist mid-generation; ADK orchestrates StreamAssist as a sub-agent/tool handle (adk_session_id ↔ stream_assist_session_id).
2. "Federated Connectors Stream 100-Page PDFs into 2M Context"
(Turn 12 Pushback Pivot)		 When corrected about Federated Connectors, the previous assistant invented a story where Microsoft Graph Federated Search streams raw 100-page PDFs into a 2M context window on every query and flushes them. Live inspection of project 545964020693 proves connectors are connectorType: "THIRD_PARTY_FEDERATED" with connectorModes: ["FEDERATED", "ACTIONS"] + bapConfig. Federated search queries Graph for ranked snippets + metadata. Full file reads only occur when Dolphin invokes fetch_documents / BAP download_document into an ephemeral per-turn RAM cache (temp:w1_document_cache, capped at 64 MB total / 10 MB per doc).
3. "Duplicate Connectors on Both StreamAssist & ADK MCP"
(Turns 1 – 22)		 Accepted connecting SharePoint & Outlook simultaneously via StreamAssist AND via custom ADK MCP servers, creating double Entra ID OAuth/WIF token pipelines and routing split-brain. Eliminate duplicate M365 connectors. Let StreamAssist own M365 Federated Search + BAP Actions (SharePoint download_document / upload_document, Outlook send_mail / create_event) under a single WIF identity (sp-wif-pool-v2), while ADK MCP servers handle custom internal enterprise systems (ERP, SQL, domain workflows).
4. "Probabilistic LLM Filter Before Memory Bank"
(Turn 22 Defense)		 Proposed letting an LLM "extraction filter" strip confidential SharePoint/Outlook facts from synthesized chat turns before calling memory_service.generate_memories(). Synthesized assistant turns blend user intent with restricted document facts at the token level. In production compliance, document facts must never enter cross-session Memory Banks. Tier 3 Memory Bank persists strictly structured user:* preferences/aliases, while all enterprise facts require live Entra ID / Microsoft Graph ACL checks on every session.

What Is Retained vs. Dropped Across ADK & Discovery Engine Spanner

SOURCE: session_content_cache.py & assist_answer.proto
TIER 1: EPHEMERAL INVOCATION RAM (DROPPED AT TURN END / IDLE / LOGOFF) TTL: 1 TURN / 0s AT REST
  • ADK temp:* State Keys (State.TEMP_PREFIX in base_session_service.py): Applied in-memory via _apply_temp_state() and stripped via _trim_temp_delta_state() before DB commit.
  • Dolphin temp:w1_document_cache (session_content_cache.py): Holds downloaded files & parsed text during the turn (capped at 64 MB total / 10 MB per doc). Garbage-collected immediately when turn finishes.
  • TextGroundingMetadata.Reference.retrieved_context (assist_answer.proto:1396): Full retrieved passage used only for LLM Pulse verification; explicitly stripped before saving to Spanner.
  • Per-User OAuth Access Tokens & SPIFFE Encrypted Egress Tokens (EncryptConnectorTokens): Held strictly in in-flight RPC memory.
TIER 2: DURABLE SESSION STATE (SPANNER & ADK DATABASE) TTL: 24H – 30 DAYS
  • ADK Master Session (adk_sessions / DatabaseSessionService): Stores adk_session_id, linked stream_assist_session_id, workflow pointers (referenced_entities: driveItemId, messageId, URI), and rolling compacted_summary.
  • Discovery Engine Spanner Sessions & AssistAnswers: Stores turn queries, synthesized answers, short citation snippets (Reference.content + DocumentMetadata URI/title), planner steps (thought: true), and Session.mcp_session_bindings.
  • Spanner Interleaved SessionCompactions (discovery_schema.sdl:1128): Asynchronous LLM summaries generated by SessionOperationsQueueHandler covering turns older than protection_window.
TIER 3: CROSS-SESSION MEMORY BANK (STRICT ACL ISOLATION) TTL: PERSISTENT
  • ADK user:* State & VertexAiMemoryBankService: Persists across all conversations for a given user_id.
  • ALLOWED (PERSISTED_USER_PREF): User formatting preferences, role/department context, timezone, recurring workflow preferences, and non-sensitive entity aliases.
  • BLOCKED (BLOCKED_ACL_DOCUMENT_FACT): Specific contract terms, financial figures, or confidential email/SharePoint contents. These are blocked from Tier 3 so revoked SharePoint/Outlook permissions take effect immediately on the next live turn.
SECTION 04 // GRAPHICAL SESSION & MEMORY LIFECYCLE STATE MACHINE

Finite State Machine: Active Execution → Idle Compaction → User Log-Off → Session Re-Hydration

4 DETERMINISTIC STATES
1. ACTIVELIVE TURN LOOP

User is actively chatting. Browser holds fresh Entra ID JWT (1h TTL) → STS mints GCP WIF token → StreamAssist queries SharePoint/Outlook with live ACLs. temp:w1_document_cache active per turn.

2. IDLE_COMPACTEDIDLE SWEEP HOOK

When user goes idle (>5m), background sweeper: (1) purges all temp:* RAM buffers & cached bearer tokens, (2) compacts turns into session.state["compacted_summary"], (3) distills safe user:* preferences to Tier 3 Memory Bank.

3. DORMANT_LOGGED_OUTZERO ACTIVE TOKENS

When user logs off or Entra token expires, session transitions to DORMANT_LOGGED_OUT. All in-memory credentials are destroyed; durable pointers (adk_session_id + stream_assist_session_id + entity IDs) remain checkpointed in SQLite/Spanner.

4. RE-HYDRATED ACTIVESEAMLESS RETURN

User returns hours/days later & signs in via MSAL. Backend reloads durable checkpoint, injects Tier 3 Memory Bank preferences + rolling summary, re-binds Discovery Engine stream_assist_session_id, and enforces fresh live Graph ACLs.
